# 発行の原子性を維持し、nodeとの整合化を段階的に進める

node-oidc-providerとの比較では、非transactionalなadapterで発行失敗後も要求の消費が残る動作と、このgemの同一DB rollbackに差がある。2026-09-30のユーザー合意により、rodauthのトランザクション内フックとDBの原子性を維持し、初版はpoll/login_hintで公開を目指しながら、より広い対応を[段階計画](../alignment-roadmap.md)で進める。再試行できるのは状態が許す場合であり、応答喪失をrollbackの証明としない[失敗時の契約](../failure-contract.md)を公開する。

## 検討した代替案

消費だけを独立して確定する案は、技術的失敗でも再承認が必要になるため採用しない。発行だけを内側のsavepointで戻す案も、外側のrollbackやプロセス停止を越えて消費を保持する保証にはならない。切替可能な複数方針は、実際の導入先で相反する要求が判明するまで追加しない。

初版の限定範囲を最終到達点とする案と、全機能の整合化を初版公開条件とする案も採用しない。将来の個別機能は、仕様・互換性・検証条件を確定してから実装する。Jevの数値は判断の補助であり、合意や正しさの証明ではない。

## 帰結

[ADR 0003](0003-follow-rodauth-hook-conventions.md)のフック契約を維持する。DB外の通知・署名サービス等の副作用はrollbackできず、導入アプリが冪等性や配送を管理する。完全なOP比較とDB別の競合・障害検証は未完了であり、この決定で免除しない。
