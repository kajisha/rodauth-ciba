# 顧客承認フローの標準インターフェースとして CIBA を採用する

初期導入先では、CS の特権アクセスについて顧客が承認した記録を監査上必要としている。独自プロトコルではなく CIBA を採用し、相互運用性とフロー上の監査記録ポイントの明確化を目指す。CIBA の OP は新規の承認サービスが担い、顧客の本人確認には既存サービスの OP を利用する。

CIBA の採用だけで監査要件への適合が確定するわけではない。監査証跡では、誰の、どの顧客に対する、何の操作が承認され、その許可に基づいて実際に何が行われたかを追跡する。初期導入先ではまずログ出力を利用する方針とし、保存要件と出力失敗時の扱いは未確定である。

公開 gem と導入アプリの責務分界は [ADR 0002](0002-limit-gem-to-ciba-op-extension.md) に記録する。

参照: [CIBA Core 1.0](https://openid.net/specs/openid-client-initiated-backchannel-authentication-core-1_0.html)
